# YuE2 实验协议

## 0. 锁定能跑的入口

记录实际训练仓库和 commit、YuE2 checkpoint、当前 reward、推理/训练入口、采样约束、可训练模块、GPU/队列、输出根目录、stem 格式及渲染器。用团队入口做 4 条 smoke（男声独唱、女声独唱、纯音乐、明确轮唱各一条），测实际用时、显存、长度、日志、歌词结构和 stem。先复用已有正常/异常样本。音频、标注、检查点保存在实验机的实验工作区。

固定几个上游序列分别渲染至少三次，比较同一序列内的 reward 波动和同 prompt 候选间差异。如果分数差主要来自渲染噪声，先固定渲染或检查可训练模块对身份有没有控制力，再考虑 RL。保存模型采样种子与渲染种子。

## 1. 生成与抽样

| 批次 | 种子与条件 | 目的 |
| --- | --- | --- |
| 开发 | `dev` 12 个曲目 × 两种独唱声线 × 4 个固定候选 = 96 条 | 调评判器、窗口/阈值、可行门和权重 |
| 确认 | `confirm` 8 个曲目 × 两种独唱声线 × 4 = 64 条 | 用冻结的指标验证真实异常和重排质量 |
| 任务探针 | `probe` 4 个曲目 × 纯音乐/轮唱两条件 × 4 = 32 条 | 检查任务输入遵循与诊断可行性；有实际接口后执行 |
| 训练效果留出 | `final` 8 个曲目 × 两种独唱声线 × 2–4 个固定候选／模型 | A/B 冻结后才解封，比较训练前后；跨曲风与中英文分别报告 |

每个种子有三个歌词段。独唱把「一个连续身份且单层主唱」放进实际 style/conditioning，男女声线均用同一歌词和风格；轮唱按表中段落的 A–B–A 或 B–A–B 分配，最后一段需要返回原角色。角色安排放在原生可用的输入字段中，同时作为结构化评分元数据保存。纯音乐使用团队已验证的纯音乐输入格式，目标为无主唱、背景人声、口白和 ad-lib。若缺少对应模式，记录条件能力并产出已有能力支持的批次。保留真实渲染长度；首批可用入口支持的 45–75 秒或等效三段结构，确认集保留至少两次段落迁移的完整音频。最终集至少加一小组较长、自然表述的 prompt 对照，记录实际时长。

使用固定候选种子（启动值 `101, 307, 587, 911`）。按完整输入创建 `conditioning_id`，按相同条件、policy 版本及采样批次创建 `group_id`。每条保存 `family_id, split, prompt_id, task_id, conditioning_id, group_id, rollout_id, style, lyrics, role_schedule, policy_commit, checkpoint_id, generation_seed, renderer_seed, sampling_config, duration_s, mix_path, vocal_path, accomp_path, generation_status`。输出可恢复，已有完整且版本一致的候选直接复用；重试同一评分或补全同一生成槽位，保留原失败记录。训练 prompt 用团队有权限且独立的数据；衍生歌词、同一曲目和音源放同一数据划分。

开发集加入用户挑出的自然漂移、正常换声区、伴奏/混响变化、少唱和无唱。可做另外的诊断对照：同一 vocal 换伴奏/响度、相近声线 A→B→A、A→B→C、纯音乐与合唱音色乐器、叠录与真双人。人工拼接或交叉淡入淡出样本标为 `synthetic`，真实模型输出标为 `natural`，指标分开报告。

## 2. 给人耳挑样本

生成带随机匿名 ID 的本地听测包，先给用户一批 24–32 对，优先展示完整 mix，备有可定位的截段和对齐时间。左右随机互换，不显示模型、训练版本、reward 结果、排序方向。需要时再听 stem 区分渲染问题与分离伪影。

- 从同 prompt 的候选中取随机对、旧/新指标分歧对，以及用户发现的自然异常。记录抽样类别，随机子样本单列；用户挑出的异常用于诊断，并另外留出随机样本估计误报。重复抽约 10% 看同一人判断的一致性。
- 在 [annotations.csv](annotations.csv) 里，`label_type` 填 `clip`、`event` 或 `pair`。曲目级 `identity_judgment` 用 `stable / drift / unsure`。事件填起止秒，`event_label` 用 `identity_drift / wrong_role / missing_vocal / extra_vocal / normal_expression / separation_artifact / unsure`，一个事件一行。配对填两个匿名 ID，身份和整体偏好各填 `first / second / tie / unsure`。最终测试为每条曲目单独记 `lyrics_pass`、`accompaniment_pass`、`expression_pass`，用 `yes / no / unsure`。
- 标签回流后先核对匿名映射、时间范围和曲目划分；盲听员无需运行模型。训练与重排的 holdout 保持冻结。小样本的单人结果说明标注者人数。

## 3. 离线重排与推进条件

在同一组已生成的候选上比较现有 reward、共同门控对照，以及四个身份分与现有 reward 的组合。用人工已决定的配对算排序一致率（预测平局按 0.5，另报覆盖），也盲听各方法真正选出的 top-1。统计真实漂移事件召回、同人表现力误罚、不可评率、漏唱/弱人声和音乐质量。对事件检测可先用预测/人工时间段 IoU ≥0.3 算一次命中，每个事件最多匹配一次，并按歌曲或 prompt 家族重采样估计区间。自然与合成结果分别出表。

在开发集比较四个指标与三个身份权重，先选盲听配对一致率高且正常唱法误报低的一个组合，性能接近时选更简单的方案。进入确认集前冻结参数与门槛。初始决策线：自然样本至少 24 个可判配对、覆盖 ≥6 个曲目家族，组合的身份偏好一致率 ≥70% 且高于共享门控对照。另要求至少 12 段人工确认的正常声区/力度变化，误报不超过 2 段；不可评分或延后组占比 ≤10%。若素材不足，扩充同分布的新曲目家族；若换 scorer，则另设新确认集。记录样本数及区间，决策线用于小试推进。

## 4. GRPO 小试与后续消融

1. **先证实独唱可学。** 用同一起点、同训练 prompt 队列、policy/decoder 配置、rollout 预算、KL 与优化参数跑 A（共享门、原 reward）和 B（共享门、原 reward 加身份项）。总预算启动值为每个实验臂尝试 80 个完整 prompt group，按 smoke 测得用时换算成 GPU 小时；共同生成秒数、token 量和实际有效步数均记录。离线候选每组 4 条；训练 G 用团队真实受支持的配置。如果实际只有 G=2，先统计小差值和可重复性；平局规则如有启用，两组同口径。正式路径若已有 KL 沿用，明确训练 logprob 与受约束 sampler 的概率口径。
2. **先冻结再测。** 同一独立留出 prompt 和种子生成 A/B，打乱盲听。主结果是身份偏好 `B 胜/(B 胜+A 胜)`，同时报告平局/不确定的比例、曲目级区间和各声线结果。初始推进线为至少 24 个可判配对（优先用每个 prompt 两个以上采样种子），B 的身份偏好胜率 ≥60%，且漏唱、表现力和伴奏各自通过率下降不超过 5 个百分点。保留训练前 checkpoint 的听感参照。样本不足或观察区间太宽时增加新留出曲目，再决定扩大训练。
3. **再测任务混合。** 独唱有收益且探针显示条件可控后，保持 checkpoint、任务配比、预算及采样相同，比混合输入的共同 reward 与混合输入的 task-wise reward。先测纯音乐、两类独唱和指定轮唱。混合 batch 内只在完整相同输入组计算 advantage，记录各任务尝试/完整/非零优势组、长度和 KL；发现困难任务贡献偏低再单独消融任务采样或归一化后的 loss 权重。各任务的最差切片与总体结果一起报告。同时合唱从专项离线验证启动。

最低产物包括环境记录、manifest、盲听包与回填标签、分量与异常时间线、离线重排表、训练配置差异、逐任务评估与可复现命令。记录每一阶段的产物路径和推进结果。
