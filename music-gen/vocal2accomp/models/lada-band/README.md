## Post-training path

LaDA-Band uses discrete masked diffusion over accompaniment codec tokens with vocal-prefix conditioning. The released `train.py` is a supervised Lightning entry point, not a GRPO trainer. A valid online RL implementation must sample multiple complete accompaniment trajectories for the same fixed vocal, retain the selected masked-token transition log-probabilities, compute group-relative advantages, and replay those exact transitions under updated and frozen policies. A reward computed on a final waveform must be attached to the full denoising trajectory. Do not substitute autoregressive token likelihood or pretend the released training entry point performs GRPO.

The 4-second official-config baseline (eight denoise steps) took 10.28 seconds after model load. The controlled Emma-vocal run has measured baseline/5/50/100/150/200/300-step 12-second replays and a separate replay on seconds 6-12 of the same recording in the [paired A/B demo](../../../../platform/site/demos/vocal-lada.html). At 100, the combined training proxy and independent Beat-v2 F1 rise, but independent STFT coverage and overall RMS fall. At 200, the onset-fit proxy increases while actual Beat-v2 F1 falls below baseline. At 300, scores rise on the overlapping 12-second replay, but accompaniment RMS overtakes the vocal; on the untrained phrase, 200 to 300 is non-monotonic. See exact values and caveats in the [GRPO run note](../../rl/grpo/README.md). Coverage-only training is now in progress; Beat-v2 and richness still need measured ablations. The combined run optimizes labeled onset/band proxies and quality guardrails, not actual Beat-v2 or a perceptual richness model. A one-singer, same-recording replay does not establish audio-quality improvement or broad generalization.
